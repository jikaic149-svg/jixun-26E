# Independent rewrite policy

本模板不把“独立重写”描述为经过法律认证的 clean-room 流程。它只表示新实现
不得复制逐飞 GPL 源码、二进制、注释、查表数据或源文件结构。

同一原则也适用于没有根许可证的 `-25E` 源码，尤其是标注 `@origin 云台` 的
文件：可以记录可观察的互操作协议和功能需求，但不复制其函数、状态机、注释、
CRC 查表或文件组织。新实现只依据 TI/器件资料和公开协议定义完成。

`tools/check_template.ps1` 只能发现架构越层、禁止的文件名和预编译库；
它不能判断重命名后的源码来源。许可证边界仍需要集中来源记录和人工审计。

每个后续新增的兼容功能应：

1. 以 TI MSPM0 SDK、芯片 TRM、外设数据手册和公开协议文档作为实现资料；
2. 使用本模板统一的 `BSP_*`、`Algorithm_*`、`Device_*` API；
3. 在模块 `README.md` 的“资料来源”小节记录资料名称、版本、链接或本地文档路径；第三方材料同时集中登记到根目录 `THIRD_PARTY_NOTICES.md`；
4. 记录可重复的测试向量、边界条件和硬件验证结果；
5. 不使用 `zf_*` 名称，不复制逐飞函数体；
6. 未完成验证的代码不进入正式源码树；验证材料留在独立工作区。

建议的 `README.md` 来源小节：

```markdown
## 资料来源

- 功能需求：
- 官方资料：
- 数据手册/TRM 版本：
- 实现人员与日期：
- 测试向量：
- 硬件验证：
- 已知限制：
```
